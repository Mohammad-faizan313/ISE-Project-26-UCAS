# ISE-A4 platform result summary (229 words)

This A4 increment implements a bounded end-to-end slice of the two-stage clinic appointment project carried forward from A1–A3. A patient signs in, creates a future appointment with a flexible arrival window, checks in during that window, and receives one queue ticket. An authorised receptionist can view the clinic queue and call a waiting ticket. The browser interface is served by FastAPI, while SQLite persists users, sessions, appointments, tickets and idempotency responses.

Server-side role and ownership checks protect patient and receptionist actions. Passwords are stored as PBKDF2 hashes and session tokens are stored as SHA-256 hashes. Check-in runs as a transaction: the appointment state update, queue-ticket insertion and saved idempotent response commit together. The unique appointment-ticket constraint prevents duplicate tickets, and repeating the same request key returns the original ticket. The arrival window is half-open: its start is accepted and its end is rejected. Staff ticket calls require an `If-Match` version; stale versions return 412 instead of silently overwriting newer state.

The combined regression suite passed 60 tests: 36 A2 domain tests and 24 A4 API/flow tests. A local server smoke check returned HTTP 200 for the health and UI routes. Test data and identities are synthetic. The scripted task walkthrough is not representative-user research. No peer review, clinic trial, production security review, accessibility audit or deployment is claimed. Clinical functions, messaging and medical-record integration remain outside scope.
